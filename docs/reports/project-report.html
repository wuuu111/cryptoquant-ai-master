01 /

项目定位

USER NEED

研究信息分散

基金净值、产品资料、市场判断与个人持仓往往散落在不同页面，难以说明“为什么推荐、为什么阻断、下一步做什么”。

APPROACH

数据、规则与解释协作

用确定性计算生成分数和权重，用硬规则约束建议，再由 LLM 解释市场、排序和裁决依据，让决策过程可检查。

DELIVERABLE

可复核的日频建议

输出候选基金、目标配置、调仓金额、阻断原因、完整协作记录及复盘，服务个人研究与本地记账。

产品边界：当前交付的是研究、建议与本地账本闭环。“一键调仓”写入本地账本，不会向支付宝、证券账户或其他外部平台发出真实交易。

04 /

Agent 如何协作

按当前 Python 工作流实现归纳为八个环节。

  1. 01

    数据与快照

    规则 / 数据

    AKShare → 净值、基准、申赎状态、资料披露。

  2. 02

    市场与历史记忆

    规则 + AI

    识别市场环境与敞口门控，检索近期周期经验。

  3. 03

    基金评分

    规则 + AI

    计算多因子综合分数，由 LLM 解释排名与争议。

  4. 04

    组合提案

    规则计算

    按保守 / 平衡 / 进取模式，生成候选及目标权重。

  5. 05

    风控与独立质询

    规则审查

    RiskAgent 检查硬规则，Critic 检查一致性与超限。

  6. 06

    Supervisor 裁决

    AI + 硬约束

    综合证据决定通过、降档、暂停、驳回或退回复算。

  7. 07

    调仓建议与账本

    规则生成

    输出金额与权重变化，供人工核验并记录本地账本。

  8. 08

    复盘与经验归档

    AI + 持久化

    形成复盘解释与研究建议，保存周期和经验供后续使用。

规则层负责可复验的计算

净值特征、基金综合分、目标权重、申赎约束、硬风控与账本计算均以确定性逻辑执行。输入数据相同，应能复现对应计算过程。

LLM 负责解释、质询与复盘

市场与评分解释、历史经验整理、Supervisor 裁决理由、复盘及研究建议采用结构化输出。调用失败时支持规则回退，硬约束继续生效。

数据与存储

“fund-graph”是项目自定义工作流名称，当前编排代码由 Python 实现；不将其描述为已经接入 LangGraph 运行时。当前默认配置为手动刷新，定时任务能力已提供但未启用。

评分与组合生成

先对六类因子进行横截面标准化并截断极端值，再按固定权重形成综合分。评分结果用于研究排序，不是收益概率预测。

综合分 = 0.30 × 动量 + 0.20 × 风险收益 + 0.20 × 趋势确认 + 0.15 × 回撤控制 + 0.15 × 市场匹配 − 0.20 × 过热惩罚

组合提供保守、平衡、进取三种分桶模式，并按市场敞口乘数缩放。当前每个类别最多挑选两只基金，单只目标权重最多 20%。实际配置可能低于模式名义比例。

净值计算特征覆盖 5 / 20 / 60 / 120 日收益、60 日波动、60 / 120 日回撤、均线及距阶段高点等。基金与指数估值 PE / PB 尚未作为当前评分因子。

风险约束与已知问题

以当前代码为准，区分规则存在与规则正确生效。

检查项当前实现实现边界
数据时效净值早于参考日期前 5 个自然日时阻断。自然日口径，尚需细化节假日处理。
申购 / 赎回增仓检查申购状态；减仓检查赎回状态。状态识别存在已定位问题，见下方。
单只权重组合生成限制 20%，Critic 检查超限。不是完整的行业或主题合计约束。
QDII / 商品单只目标分别检查 20% / 15% 上限。尚未实现同类资产合计上限。
防守配置风控后债券与现金类目标合计至少 10%。只统计保留的基金目标，尚需完善未投资现金口径。
换手约束正常敞口模式且已有持仓占比 ≥50% 时，绝对权重变化合计超过 30% 将触发阻断。有适用前提，不是所有环境下一律执行。
最终裁决当硬风控或独立质询阻断时，不允许直接通过。LLM 不能豁免确定性检查。
已定位、尚未修复的状态误判：当前风控只把英文 open 识别为开放；源站的“开放申购”和“场内交易”会被当成关闭。因此最近周期的整批阻断不能直接理解为真实停售。被剔除的防守基金又可能连带触发最低配置不足。需要先修复状态标准化与交易渠道区分，再重跑验证。

运行与使用入口

本地启动

以下命令在基金服务目录执行；使用已安装好的 Python 与前端依赖环境。

# 后端
FUND_AGENT_CONFIG=config.real-local.yaml .venv-fund/bin/python -m uvicorn app.main:app   --host 127.0.0.1 --port 8710

# 另一个终端：前端
cd frontend
npm run dev -- --port 5174

前端通常访问 http://127.0.0.1:5174，后端健康检查为 http://127.0.0.1:8710/health。如端口被占用，以启动日志为准。

数据与模型配置

config.real-local.yaml 保存研究基金池、数据源、数据库和工作流设置；.env 可保存 LLM 密钥。报告不包含密钥、个人余额或交易流水。

一次完整的日常使用

  1. 同步净值与申赎状态，确认数据日期。
  2. 查看账户预算和本地持仓是否准确。
  3. 运行一次日频周期，阅读阶段结论与裁决依据。
  4. 核验平台是否上架、申购限额和持有期。
  5. 真实操作在用户的购买平台完成，再记录本地账本。

在当前已知的状态误判修复前，应先复核阻断来源，不能把现有建议直接当成可执行平台指令。
